1. What the platform is

The platform is the team's EthioEMR (OpenMRS 3, TenaEHR) exactly as it is on GitHub main, plus the modules built on top of it that are not in the published images yet. distro/ is a byte-for-byte copy of palladium-group/ethiopiaemr-distro-referenceapplication at commit 9147129. Everything specific to the platform lives in one overlay compose file, the gateway template and modules/.

2. Architecture

One gateway on port 18200 decides where each browser request goes. The team's frontend and backend images are used unchanged; the platform adds a module overlay, an AI configuration file and a local speech service.

Request routing in the gateway

The gateway is the team's nginx image with gateway/platform.conf.template mounted in place of its default template.

PathServed from
/openmrs/spa/importmap.json, /openmrs/spa/routes.registry.jsonwork/spa-overlay/: the team's app list and routes merged with this repo's modules. Never cached.
/openmrs/spa/overlay/<module>/work/spa-overlay/modules/: the built Form Studio and AI assistant files.
/openmrs/spa/ai-assistant.config.jsonGenerated by nginx from .env at container start (section 8).
/openmrs/spa/config/The frontend's /config/ (logos, icons, translations).
/openmrs/spa/*The team frontend container, full path passed through.
/openmrs/*The team backend (OpenMRS), which reads the MySQL database and the Initializer content in content/.

The browser calls two services directly: the remote AI service (https://emr-ai.20.84.70.78.nip.io) and the local speech service (http://localhost:8767). The gateway's Content-Security-Policy allows both through AI_CONNECT_SRC.

4. Running it

Windows, PowerShell, from the repository root. platform.ps1 is the one entry point; it wraps docker compose --project-directory . -f distro/docker-compose.yml -f docker-compose.platform.yml.

Quick start

  1. copy .env.example .env, then set AI_SERVICE_API_KEY (ask the AI service owner). platform.ps1 creates .env from the example if it is missing.
  2. .\platform.ps1 up starts the stack. See the timings below.
  3. .\scripts\build-form-studio.ps1 makes the production build of Form Studio.
  4. .\platform.ps1 overlay adds Form Studio and the AI assistant to the app. Refresh the browser.
  5. Optional: services\asr-service\start-asr.ps1 starts the speech service for Speak, in its own window.

Commands

CommandWhat it does
upStarts the stack. On an empty install with a snapshot present it restores the snapshot first. Without a snapshot or a dump it runs scripts/get-initial-db.ps1.
overlayRuns tools/build-spa-overlay.py and restarts the gateway. Run after start and after any module rebuild.
statusContainers and health (docker compose ps).
logs [service]Follows the logs of one service or all.
stopStops the containers and keeps data.
downRemoves the containers and keeps the data volumes.
configPrints the merged compose file. Must succeed before a PR.
content-passFresh install only, after the first start: clears the Initializer checksums and restarts the backend for a second content pass.
snapshotStops backend and db, saves the two data volumes to database/snapshots/, starts them again.

How long it takes

Measured on 2026-10-22.

StartTimeWhy
Normal restart (stop then up)about 3.5 minData is kept in the Docker volumes.
Fresh install with a snapshot in database/snapshots/about 6 minup restores the loaded database and OpenMRS data.
Fresh install without a snapshotabout 1.5 hDatabase import, search index over about 81,000 concepts, all content, then content-pass.

Snapshot procedure

  1. Finish one full first start, including .\platform.ps1 content-pass.
  2. Run .\platform.ps1 snapshot. It writes mysql-data.tgz and openmrs-data.tgz (about 900 MB together, git-ignored) and restarts backend and db (2 to 3 min).
  3. Copy database/snapshots/ to teammates. On their empty install, up finds both files and restores them before starting.

Content pass

The Initializer saves checksums even for content files that failed, and some files refer to concepts defined in later files. content-pass deletes /openmrs/data/configuration_checksums and restarts the backend so every file is processed again. Afterwards check:

docker logs ethioemr-platform-backend-1 2>&1 | Select-String 'was processed and [0-9]+ out of'

The expected result is no lines. Today about 19 files still appear (section 12).

7. Extra frontend modules (the overlay)

The published frontend image does not contain Form Studio or the AI assistant. Until each is published to npm and listed in the distro, tools/build-spa-overlay.py adds them:

  1. It reads the frontend container's own importmap.json and routes.registry.json.
  2. For each modules/<name>/module.json it copies the built files to work/spa-overlay/modules/<name>/ (source maps skipped unless --keep-maps).
  3. It adds one import map entry per module, pointing at ./overlay/<name>/<entry>, and adds the module's routes.json to the route registry. App shell 10.x keeps routes under a top-level routes object; the script handles both layouts.
  4. The gateway serves the merged files in place of the frontend's, with Cache-Control: no-store, so a rebuild shows on refresh.
module.json keyMeaning
packagenpm package name, for example @palladium-ethiopia/esm-form-studio-app.
distFolder with the build: relative path, absolute path, or $ENV_VAR.
entryEntry file. Optional; defaults to <scope>-<name>.js.

Adding a module

  1. Build it (production). The build must contain routes.json, or the script stops with "no routes.json".
  2. Add modules/<name>/module.json with package, dist and entry. Copy one of the two existing files.
  3. Run .\platform.ps1 overlay and refresh the browser. Check that the browser console has no new errors.

The team's long-term route is to publish the module to npm and add one line to distro/frontend/spa-assemble-config.json in the distro repository. After that the overlay is no longer needed for it.

8. AI assistant configuration in the gateway

The AI assistant needs three values in the browser: the AI service address, its API key and the speech service address. They come from .env, so the key is not stored in any repository or image.

The config file

nginx answers /openmrs/spa/ai-assistant.config.json itself. The template fills it from the gateway's environment when the container starts:

{"@palladium-ethiopia/esm-ai-assistant-app":
  {"aiServiceUrl":"${AI_SERVICE_URL}","aiServiceApiKey":"${AI_SERVICE_API_KEY}","asrServiceUrl":"${ASR_SERVICE_URL}"}}

Why a sub_filter is needed

The app shell loads the config files listed in index.html. The published frontend image fixes that list at build time, so the SPA_CONFIG_URLS variable in the compose file is ignored. The gateway therefore edits the page as it passes through:

proxy_set_header Accept-Encoding "";
sub_filter_once on;
sub_filter 'configUrls: [' 'configUrls: ["/openmrs/spa/ai-assistant.config.json", ';
DetailReason
Placed first in the listLater files win. The AI file sets only the assistant's own keys, so the team's files keep the last word.
Accept-Encoding ""sub_filter can only edit an uncompressed response, so the gateway asks the frontend for one.
CSP connect-srcThe browser may call only the addresses in AI_CONNECT_SRC besides the EMR itself.

Check it: http://localhost:18200/openmrs/spa/ai-assistant.config.json returns the three values (the key included, see section 13).

9. Speech service

The Speak button needs speech-to-text, and the EMR images do not include it. services/asr-service is that service, run locally on 127.0.0.1:8767. Audio never leaves the machine.

EndpointBehaviour
GET /health{"status":"ok","model":"..."}. The assistant then shows "Speech service ok" with the model name.
POST /transcribeForm with audio (WAV) and lang (en or am). Returns text, model, processing_time; for Amharic also what each engine heard and english_words_used.

Start it

.\start-asr.ps1 in services/asr-service. The first run creates .venv and installs about 3 GB of Python packages; the models (about 3.5 GB) download into the shared Hugging Face cache on first use. Leave the window open. After the platform's first start, rebuild the medical vocabulary from the EMR database with python build-lexicon.py.

Mixed Amharic and English

In mixed mode (the default) two engines run on the same recording and mix.py merges them word by word, without an LLM. The Amharic engine hears everything but writes English words in Amharic letters. An English word from Whisper replaces what the Amharic engine heard at the same moment only if Whisper is reasonably sure, it sounds like the Amharic engine's word, and it is in the EMR's own vocabulary (lexicon\emr-vocab.txt, about 29,000 words from concept and drug names). Every output word comes from one of the two engines.

SettingDefault in server.py and start-asr.ps1Meaning
ASR_MODELmobiuslabsgmbh/faster-whisper-large-v3-turboEnglish Whisper model (lead).
ASR_CONFIRM_MODELsmallSecond English model that confirms words; empty turns it off.
ASR_AM_MODEmixedmixed or transcribe (Amharic engine only).
ASR_DEVICEautoauto, cuda or cpu.
ASR_SAVE_DIR(off)Saves each recording; -SaveRecordings sets it.
ASR_PORT8767Port.

The Amharic engine is agkphysics/wav2vec2-large-xlsr-53-amharic: 9% character errors on the 15 s test consultation, 3 s on CPU. Whisper large-v3 alone gave 90% character errors on Amharic and was rejected.

Amharic needs a setting. The assistant's asrLanguage defaults to en. Set it to am in Implementer Tools; it is stored in the browser only (local storage key openmrs:temporaryConfig).

End-to-end suite

Playwright drives the installed Chrome through Form Studio the way a form builder would. The harness refuses any address that is not localhost, runs one browser at a time, logs in once, closes the EMR's red "unresolved backend dependencies" pop-up and accepts "Leave site?" dialogs. The login lives in e2e/.env (copy e2e/example.env; git-ignored). Reports go to work/e2e-report/.

13. Security notes

Caution

Any user who can open the EMR can read the AI service API key in the browser. The gateway keeps it out of git and images, but /openmrs/spa/ai-assistant.config.json returns it to every page, like any frontend configuration.

Open items for the AI service owner, most urgent first:

#ItemQuestion
1Rotate the keyIt was distributed in the AI quick-start zip and images. What can a holder of the key do: which endpoints, what rate limit, can it reach endpoints that take patient context?
2Canonical address and TLSConfig uses emr-ai.20.84.70.78.nip.io, the integration docs say ai.20.84.70.78.nip.io. Which is canonical, and can it get a trusted certificate?
3CORS_ORIGINSWhich origins are allowed? Calls from http://localhost:18200 already succeed, which suggests a wildcard or no origin check.
4User identityX-OpenMRS-User is trusted but not verified. When does the same-origin route /openmrs/ai/ with OpenMRS session validation arrive? It removes the key from browsers.
5Patient data handlingAre prompts, chart records or answers logged? Where, for how long, and who can read them?
6Frontend on shell 10.xRebuild against 10.0.1-pre.5263 with peer 10.x, publish @palladium-ethiopia/esm-ai-assistant-app to npm, share the source repository.

Other rules: secrets (.env, keys) never go into git; the platform holds synthetic test data only; the speech service listens on 127.0.0.1 only and keeps audio on the machine; recordings saved with -SaveRecordings must be test dictations only.

14. Conventions

From CONTRIBUTING.md, following the team distro.

TopicRule
Branchesmain is the integration branch; never commit to it. Branch from it with feat/, fix/, chore/ or docs/. One topic per branch and per PR.
MergesPRs are merged with a merge commit ("Merge pull request #N from ...").
CommitsConventional Commits: feat: ..., fix(gateway): ..., chore: pin distro to sha-9147129. Imperative, present tense, about what changes and why.
Other teams' codedistro/ and content/ are copies. Fix upstream, then refresh.
Before a PR.\platform.ps1 config succeeds; after overlay or module changes, the browser console is free of new errors; after speech changes, test-merge.py shows "(no swaps)"; the PR says where a reviewer can see anything new.
